### [Monolite](https://github.com/Tanke6003/monolite) — a TypeScript backend toolkit you adopt one package at a time

<p>
  <img src="https://img.shields.io/github/license/Tanke6003/monolite?style=flat-square" alt="License" />
  <img src="https://img.shields.io/badge/version-0.8.0-orange?style=flat-square" alt="Version" />
  <img src="https://img.shields.io/badge/packages-7-lightgrey?style=flat-square" alt="Packages" />
  <img src="https://img.shields.io/github/last-commit/Tanke6003/monolite?style=flat-square" alt="Last commit" />
</p>

Not a framework that owns your `main.ts` — a set of small packages that solve the parts of a
backend most templates leave to you. Every package works on its own; install the one you need
and ignore the rest.

- **`monolite-data`** — one `IGenericRepository<T>` over in-memory, Oracle, SQL Server, PostgreSQL, MySQL and MongoDB. Engine differences live behind a `SqlDialect`, so switching databases is a config change plus one dialect object, not a rewrite. DDL and migrations are generated from the same mapping.
- **`monolite-http`** — decorator-based routing (`@ApiController`, `@Get`, `@Post`) with Zod validation and an OpenAPI 3.1 document generated from the routing metadata instead of maintained beside it.
- **`monolite-crud`** — five endpoints per entity from a `@Crud()` decorator, each one overridable, with ambient transactions via `@Transactional()`.
- **`monolite-auth`, `monolite-core`, `monolite-di`** — optional JWT auth and guards, zero-dependency contracts, and a composition root kept separate so nothing else depends on a container.
- **`monolite-cli`** — `monolite new` scaffolds a project and asks which database you want; `monolite generate` writes modules, entities, BLLs, controllers and repositories into it.

**Engineering practices behind it:** npm workspace with TypeScript project references, ~1,100 unit
assertions, a scaffold suite that generates five projects and type-checks every file each one
writes, documentation examples compiled in CI in both languages, and an integration suite that runs
the full repository contract against PostgreSQL, MySQL, SQL Server, Oracle and MongoDB on every
push. Bilingual docs, changelog, contributing guide and security policy included.

### [ApiBaseNetCore](https://github.com/Tanke6003/ApiBaseNetCore)

A Clean Architecture starter solution for building ASP.NET Core Web APIs.

- **Web API layer** — controllers, DTOs and middleware ready to extend
- **xUnit test project** — sample unit and integration tests included
- **`Notes.md`** documenting Domain, Application, Infrastructure and Presentation layers
- **Best-practice structure** for layered separation of concerns out of the box

### [api-ts-express](https://github.com/Tanke6003/api-ts-express)

A TypeScript-first Node.js API boilerplate for fast, production-ready back-end services.

- **Clear folder structure** — `presentation`, `domain`, `application`, `infrastructure`
- **Environment templates** — `.env.template`, `.env.test`, `.env.dev`
- **Containerized dev** — `docker-compose.yml` for a local MSSQL database
- **Testing out of the box** — Jest with sample tests under `tests/`
- **CI/CD ready** — GitHub Actions workflows under `.github/workflows/`
- **API documentation** — auto-generated OpenAPI docs (`swagger` / `scalar`)

### [cron-task](https://github.com/Tanke6003/cron-task)

A lightweight TypeScript/JavaScript module for scheduling and managing recurring jobs
using cron expressions or millisecond intervals.

- **Dynamic task CRUD** — add, update or remove tasks by ID, name or category
- **Filtering** — query tasks by name, ID or category
- **Control** — start/stop individual tasks or whole categories at once
- **UUID-based IDs** with built-in support for cron syntax and plain intervals

> Ideal for automating maintenance scripts, report generators or background jobs in Node.js.

## 🏠 Homelab

Most of what I know about infrastructure I learned by breaking it at home first. I self-host my
own services to understand the whole stack instead of just the application layer — reverse proxies
and TLS, containers, backups, monitoring, and the unglamorous part where something dies at 2 a.m.
and you have to figure out why.

It's also where I prototype the platforms I build for real: if an idea survives my own hardware,
it's probably worth shipping.
